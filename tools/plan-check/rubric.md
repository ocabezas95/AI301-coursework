# Rubric: is this plan ready to post and build from?

## Checks

| Check                       | Evidence                                                                                                                                                                                                                                                               | Pass condition                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | Weight   |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| `diagnosis-grounded`        | The plan's stated cause, read against the behavior the repro-evidence block pins down: its steps, the outcome it observed, and its quoted artifacts (live: the student's posted repro comment on the issue, or the house repro pack as quoted in the drafts).          | Passes if the stated cause accounts for every behavior the repro evidence shows and contradicts none of it: an artifact the cause cannot explain, or a cause the artifacts rule out, is a fail. Also fails if the plan's diagnosis does not engage the repro evidence at all (it would read the same without the repro). **No repro, no grounding:** if the package quotes no repro evidence, this check is graded **fail**, never `unclear`, because a diagnosis with nothing to stand on is ungrounded by definition.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | required |
| `targets-cause-not-symptom` | Where the plan's proposed change lands (the function, module, or layer it edits), read against where the repro evidence locates the fault: the stack frames, the origin of the bad value, the step at which behavior first diverges.                                   | Passes if the change targets the deepest layer the repro evidence implicates, not the place where the symptom surfaces. **When the evidence cannot localize the cause,** passes if the plan targets the deepest layer the evidence does show **and** says the rest of the cause is unconfirmed. Fails if the change suppresses or works around the symptom (catching the exception, guarding at the display layer, special-casing the reported input) while the evidence points upstream of it. Fails the same way as `diagnosis-grounded` if the package quotes no repro evidence.                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | required |
| `scope-bounded`             | Every change the plan proposes (its scope statement, the files or areas it names, and its approach), read against the behavior the issue describes.                                                                                                                    | Passes if every proposed change is needed to fix this issue's behavior. Fails if the plan includes any refactor, rename, style cleanup, dependency bump, new feature, or fix for an adjacent bug that the plan does not show the fix depends on. Mentioning adjacent problems as a separate follow-up is fine; folding them into this change is not. Judge the change itself, not whether the plan has a "not in scope" section.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | required |
| `executable-by-stranger`    | The plan's description of what will be done (files or areas, approach, order of work), read as someone who has the repo but has never spoken to the author.                                                                                                            | Passes if the plan names **where** the change goes (a file, module, or function, or a location the issue or repo-facts block makes unambiguous) **and what** the change is, so a stranger could make the first edit without asking the author anything. Fails on a verb with no object or no location ("fix the parser", "improve error handling", "clean up the logic"), or when the plan depends on knowledge only the author has.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | required |
| `test-plan-decisive`        | The plan's test plan, read against the repro evidence's steps and its artifact (the error, output, or value that showed the bug).                                                                                                                                      | Passes if the test plan names at least one check, either an automated test or a re-run of the repro steps, with a concrete observable outcome that **fails on current code and passes after the fix**, tied to the repro's trigger and artifact (same input, same observable). Fails on "run the test suite", "verify it works", "make sure nothing breaks", on an outcome that would already pass on current code, or on a test of behavior other than the reported bug.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | required |
| `unknowns-stated-honestly`  | Each assertion in the plan and the plan comment (about cause, side effects, other callers, compatibility, effort, or timeline), read against what the issue context, repro evidence, and repo-facts block actually show.                                               | Passes if every assertion the package cannot support from its own evidence is marked as a hypothesis or an open question, and the plan comment asserts nothing the plan does not commit to. A plan with no stated unknowns passes **only if** everything it asserts is evidenced. Fails if an unevidenced claim is stated as fact ("this is the only caller", "no other behavior changes", "this will be done by Friday"), or if the comment promises more than the plan contains.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | required |
| `thread-aware`              | The plan comment and the plan's approach, read against the issue's maintainer signals: thread highlights in the issue context (maintainer comments, labels, directions suggested or ruled out). Live: the issue thread itself.                                         | Passes if, where a maintainer has suggested a direction or ruled one out, the plan either follows it or explicitly says why it departs and what it does instead. **No maintainer signal is a pass**, graded with evidence `no maintainer direction in thread`, never `unclear`. Fails if the plan proposes an approach the thread ruled out, silently ignores a maintainer's suggestion, or piggybacks on another commenter's plan ("same approach as above"). Another commenter's or classmate's plan does **not** fail this check (house rule, `scope.md`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | required |
| `repo-policy-respected`     | The plan comment and plan, read against the repo's stated rules in the repo-facts block (contributing asks, comment or PR templates, contribution policy, AI-use disclosure policy). Live: CONTRIBUTING and templates in the repo, plus the house rules in `scope.md`. | Passes if every stated repo rule that applies to a plan comment or the planned work is satisfied (for example, a required template's fields filled with real content, or a required "discuss before PR" step respected). **AI-use disclosure is checked as present-or-absent in the package text:** where the repo requires AI use to be disclosed, the package must carry a disclosure line naming the tool and the extent of the assistance, and its absence is a **fail**, never `unclear`. A package graded by this skill is AI-assisted, so "I cannot tell whether AI was used" is not an available reading. After the build begins, when this check runs against the student’s fork and a branch is available, it must be named `<type>/<issue-number>-<slug>`, where `<type>` is one of `fix`, `docs`, `feat`, `test`, `refactor`, `perf`, or `chore`. Before a branch is created, its absence does not affect initial plan readiness. Beyond these, fail only on a rule the package can be checked against; tone, length, and phrasing are out of scope. | required |

## Verdict rule

**Accept** (ready to post and build from) if every `required` check is
graded `pass`. Any single `required` check graded `fail` or `unclear`
produces **reject** (hold): a plan whose readiness cannot be verified
from the package is not ready to build from.

`preferred` checks, if any are added, are graded and reported but never
change the verdict.

Three readings are fixed so that `unclear` cannot stand in for them:

- **No repro evidence quoted:** `diagnosis-grounded` and
  `targets-cause-not-symptom` are graded `fail`, not `unclear`, so the
  package is rejected.
- **No maintainer signal in the thread:** `thread-aware` is graded
  `pass`, not `unclear`.
- **AI-use disclosure required but absent:** `repo-policy-respected` is
  graded `fail`, not `unclear`.

For the output, the deciding check's evidence line quotes the fact or
passage that failed it. When several required checks fail, report each
failure; the verdict is reject either way.
