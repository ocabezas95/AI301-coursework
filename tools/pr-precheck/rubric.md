## Verdict rule

**Accept** (ready to submit) if every `required` check is graded `pass`.
Any single `required` check graded `fail` or `unclear` produces
**reject** (hold): a PR whose readiness cannot be verified from the
package is not ready to submit, so `unclear` always counts against
acceptance.

`preferred` checks, if any are added, are graded and reported but never
change the verdict.

Six readings are fixed so that `unclear` cannot stand in for them:

- **No `plan.md` in the package:** `plan-fidelity` is graded `fail`.
- **No test evidence quoted:** `tests-evidenced` is graded `fail`.
- **A required check's output is shown as non-passing or empty, with a
  stated reason:** this does not fail `tests-evidenced`.
- **No `## Deviations` section, and the diff matches the plan:**
  `plan-fidelity` is graded `pass`.
- **No maintainer request in the thread:** `repo-policy-respected` is
  not failed on that basis.
- **AI-use disclosure absent:** `repo-policy-respected` is graded
  `fail` in live mode, and in eval mode when the bundle's repository
  requirements require disclosure. In eval mode with no such
  requirement, its absence does not fail the check.

For the output, each failing check's evidence line quotes the hunk,
output, or passage that failed it. When several required checks fail,
report each failure; the verdict is reject either way.
