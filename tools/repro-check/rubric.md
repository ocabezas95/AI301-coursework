# Rubric: is this reproduction package ready to post?

## Checks

| Check                       | Evidence                                                                                                                                                                                                   | Pass condition                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | Weight    |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| `claim-targets-issue`       | The claim comment, read against the issue's title and body (live: the issue thread; the draft claim file in the working directory).                                                                        | Passes if the claim names the behavior _this_ issue describes in the claimant's own words — enough detail that a reader can tell the claimant read past the title. Fails if the claim describes a different problem than the issue, restates the title alone, or piggybacks on another commenter's work ("same as above"). A prior claim by someone else does **not** fail this check (see the Comms house rule in `references/evidence-guide.md`).                                                                                                                                                                                                                                          | required  |
| `environment-reconciled`    | The repro report's environment record, read against the version/OS/runtime target stated in the issue context (and the repo-facts block, where present).                                                   | Passes if the report names the concrete environment it ran on (OS, runtime/language version, and the package or repo version under test) **and** those values match the issue's stated target, **or** the report explicitly calls out where they differ. Fails if no concrete environment is named, or it differs from the issue's target with no mention.                                                                                                                                                                                                                                                                                                                                   | required  |
| `steps-followable`          | The reproduction steps in the repro report, read as a reader of the thread sees them: the report plus the issue it answers, and nothing else.                                                              | Passes if the steps run from a stated starting state through to the trigger with no gap a reader would have to guess at — every command, input, file, and setup action the run depended on is available. **Steps may reuse the issue's own reproduction by reference** ("ran the issue's script verbatim") when the report names the specific inputs and parameters it used, so the reference resolves to one unambiguous thing; the issue body counts as supplied. Fails only if reaching the reported outcome requires something **neither the report nor the issue provides** — an unlisted dependency, an unnamed config, an unstated data file, an unspecified starting state. | required  |
| `behavior-matches-issue`    | The artifacts in the repro report (output excerpt, log, stack trace, screenshot), read against the error or symptom the issue describes.                                                                   | Passes if a quoted artifact shows the issue's specific signature — the same error, message, or symptom the issue reports — not merely a failure in the same area. **Cannot-reproduce clause:** a report that states it could not reproduce passes this check if it shows an artifact of what happened instead (the command succeeding, the expected output) under the issue's steps and a reconciled environment. Fails if the artifact shows an adjacent or different error than the one the issue describes, or if the outcome rests on prose with no artifact behind it.                                                                                                                  | required  |
| `claims-backed-by-evidence` | Each assertion in the claim comment and the repro report, read against the artifacts the same package shows.                                                                                               | Passes if every assertion the package makes is supported by something the package itself shows — the outcome stated is the outcome the artifact shows, and any cause, scope, or fix suggestion is marked as a hypothesis rather than asserted. An honest, evidenced cannot-reproduce is a pass here. Fails if the package asserts more than its artifacts show: a confirmed reproduction with no matching artifact, a diagnosis stated as fact, or a scope claim ("affects all versions") the run never tested.                                                                                                                                                                              | required  |
| `repo-policy-respected`     | The claim comment and repro report, read against the repo's stated rules in the repo-facts block (live: CONTRIBUTING, issue/comment templates, AI-use disclosure policy) and any house rule in `scope.md`. | Passes if every stated repo rule that applies to these comments is satisfied. **AI-use disclosure is checked as present-or-absent in the package text:** where the repo requires AI use to be disclosed, the package must carry a disclosure line naming the tool and the extent of the assistance, and its absence is a **fail**, never `unclear` — a package graded by this skill is AI-assisted, so "I cannot tell whether AI was used" is not an available reading. A required comment or issue template's required fields must likewise be filled with real content. Beyond these, fail only on a rule the package can be checked against; tone, length, and phrasing are out of scope. | required  |
| `specific-not-boilerplate`  | The wording of the claim comment and repro report, read against the issue's particulars.                                                                                                                   | Passes if the comments say things only someone who actually ran this could say — this issue's specific commands, values, paths, or observations — rather than filler that would read identically on any issue. Never changes the verdict.                                                                                                                                                                                                                                                                                                                                                                                                                                                    | preferred |

## Verdict rule

**Accept** (ready to post) if every `required` check is graded `pass`. Any
single `required` check graded `fail` or `unclear` produces **reject**
(hold) — evidence that cannot be verified is not evidence that is ready
to go upstream.

`preferred` checks are graded and reported but never change the verdict.

**Claim-only drafts** (live mode, per SKILL.md): the checks whose evidence
is the repro report — `environment-reconciled`, `steps-followable`,
`behavior-matches-issue` — are reported `unclear` with evidence
`not yet applicable: claim-only draft` and are **excluded** from the
verdict rule. The verdict is then decided by `claim-targets-issue`,
`repo-policy-respected`, and the report-independent portion of
`claims-backed-by-evidence` (the claim comment's own assertions), and it
answers only: is this claim comment ready to post? This exclusion applies
only to a claim-only draft; in a full package or in eval mode, `unclear`
on any required check is a reject.
